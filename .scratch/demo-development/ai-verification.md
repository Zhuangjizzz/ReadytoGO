# AI 服务实施与联调记录

日期：2026-10-09（Asia/Shanghai）。工单：[05](issues/05-ai-service.md)。

## 设计与边界

- 基础 `openai` Node SDK 调用既有千问 `qwen3.8-flash`，地域 `cn-beijing`；读取既有服务端环境，凭据未写入代码、记录或响应。
- 行程解析、候选设施分析、模糊资料匹配各有独立 JSON 契约。应用先取数再分析，不建设通用工具平台。
- `/api/v1/assist/parse` 返回 `status`、原文、待确认检索词、逐站备注、显式需求及不支持需求。地点原文须逐项对应输入中的顺序片段；保留重复与超过 10 站的结果。模型内部的 `preferenceEvidence` 须对应输入原文，公开响应只给提议。
- 每次 AI 操作初次输出与最多一次 JSON 修复共用 12 秒硬截止；SDK `maxRetries: 0`，限流/鉴权/网络错误直接回退。超时即使外部边界不响应取消也会回退。
- 设施分析按现有每批候选一起调用。ID、枚举、长度、依据字段、正面设施线索与原始肯否定都检查后才采用；模型输出不能改坐标、路线或排序。模型只给定性设施说明，服务端从真实 `walkSeconds` 补分钟，并从既有字段补门票或消费要求。
- 候选分析缓存 15 分钟，包含需求、语言、查询上下文、进入设置、范围、起点、候选及其设施/路线数据；缓存最多 256 项。英文辅助名在内存复用，最多 2,000 项。匹配决策按 POI 与召回记录内容缓存 15 分钟、最多 512 项。
- 资料匹配只向模型提供同区、位置邻近、名称或地址相似且道路/门牌不冲突的最多四个 ID；无法判断保留高德独立候选。后台召回的数量与时序由查询服务统一控制。
- 日志保持现有请求 ID、路由、状态与耗时，不写用户行程、精确位置、供应商原始响应或密钥。

## 真实模型检查

通过产品 HTTP 入口调用，使用专门编写的演示文本；不是用户真实行程。以下时间为本地 HTTP 请求至业务响应耗时。所有响应 HTTP 200、`status=complete`。

| 输入范围 | 关键观察 | 耗时 |
| --- | --- | --- |
| 英文：中国美术馆 → 五道营胡同，要求 Western-style seated toilet 与 baby-changing | `seated_required`；两地顺序保留；额外需求进入 `unsupportedNeeds`。首次时间前缀未保留，见下方改进。 | 2,023 ms |
| 中文：陶然亭公园 → 北京天文馆 → 陶然亭公园，不需要坐便、询问厕纸 | `any`；保留重复的第三站；厕纸进入 `unsupportedNeeds`。 | 2,840 ms |
| 英文：什刹海 → 自拟名称 Blue Window Gallery，祖父母同行 | `proposedPreference=null`，未从同行人推断坐便；保留不确定画廊的原名及检索词供用户编辑。 | 2,095 ms |
| 英文：Friday 10:45 首都博物馆，14:00 玉渊潭，晚饭前回首都博物馆，无特殊需求 | `any`；日期/时间前缀、下午时间与返回备注均保留；重复站保留。 | 3,384 ms |
| 中文：明天上午九点半红砖美术馆，下午两点今日美术馆，同行者明确要求坐便和无障碍通道 | `seated_required`；两个时间备注保留；无障碍通道进入额外需求。 | 2,488 ms |

首次调用发现时间前缀遗漏后，补充了通用解析规则：所有明确时间与日期必须放入对应站点备注，前置日期/时间归首站，返回前检查是否遗漏。后两条使用不同地点及不同时间表达复验。没有添加具体景点、评测句子或测试名称的生产分支，也未要求模型对固定样例作固定回答。

## 自动化验证

公开 HTTP 边界覆盖解析、2000 字符上限、重复/超站候选、显式/否定/无需求、非法 JSON 修复、ID/字段校验、超时、限流回退；地图与模型在外部供应商边界替换。候选与匹配检查在查询服务接入后补全。
