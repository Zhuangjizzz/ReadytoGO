# AI 服务实施与联调记录

日期：2026-10-09（Asia/Shanghai）。工单：[05](issues/05-ai-service.md)。

## 设计与边界

- 基础 `openai` Node SDK 调用既有千问 `qwen3.8-flash`，地域 `cn-beijing`；读取既有服务端环境，凭据未写入代码、记录或响应。
- 行程解析、候选设施分析、模糊资料匹配各有独立 JSON 契约。应用先取数再分析，不建设通用工具平台。
- `/api/v1/assist/parse` 返回 `status`、原文、待确认检索词、逐站备注、显式需求及不支持需求。地点原文须逐项对应输入中的顺序片段；保留重复与超过 10 站的结果。模型内部的 `preferenceEvidence` 须对应输入原文，公开响应只给提议。
- 行程解析与单次匹配操作初次输出和最多一次 JSON 修复共用 12 秒硬截止；最多 10 项的候选分析共用 20 秒硬截止；SDK `maxRetries: 0`，限流/鉴权/网络错误直接回退。超时即使外部边界不响应取消也会回退。
- 设施分析按现有每批候选一起调用。ID、枚举、长度、依据字段、正面设施线索与原始肯否定都检查后才采用；模型输出不能改坐标、路线或排序。模型只给定性设施说明，服务端从真实 `walkSeconds` 补分钟，并从既有字段补门票或消费要求。
- 候选分析缓存 15 分钟，包含需求、语言、查询上下文、进入设置、范围、起点、候选及其设施/路线数据；缓存最多 256 项。英文辅助名优先使用已有来源英文名；其余使用确定性拼音转写与通用 `Public restroom` 设施词，中文原名和地址保留。模型不再输出英文名称，以免扩写含混缩写为错误机构。辅助名以 `phonetic-v1` 缓存键在内存复用、最多 2,000 项，旧模型译名不复用。匹配决策按 POI 与召回记录内容缓存 15 分钟、最多 512 项。
- 资料匹配只向模型提供同区、位置邻近、名称或地址相似且道路/门牌不冲突的最多四个 ID；无法判断保留高德独立候选。每个查询最多选择两处有合法召回池的 POI，批内并发匹配，先保存规则候选再等待有限匹配结果；没有可召回记录的 POI 不消耗匹配次数。数量与时序由查询服务统一控制。
- 日志保持现有请求 ID、路由、状态与耗时，不写用户行程、精确位置、供应商原始响应或密钥。

## 真实候选与预算校准

公开地图演示起点的真实高德候选、路线与本地资料经产品 HTTP 搜索接口完成批量分析。最初 12 秒的候选预算出现一次回退；后续诊断的 10 项模型调用为 11,714 ms，已经没有足够修复余量。将候选分析总预算改为 20 秒（解析/匹配仍为 12 秒），不是增加 SDK 自动重试。修改后的英文批次模型耗时 12,143 ms、整体查询 21,576 ms，均 `complete`。

真实输出也暴露了含混专名缩写被扩写为错误机构的问题。通用提示约束未足以避免该错误，因此移除模型的名称输出：已有真实英文名称保留，否则专名使用确定性拼音、通用设施词使用英文。这不是景点专用词表。调整后仅做一次必要的完整泛化检查：中文 10 项分析 8,528 ms、整体 HTTP 查询 17,281 ms，`analysisStatus=complete`，`pendingWork=false`；设施说明为中文，辅助名为拼音加设施词。示例中路线真实为 329 秒，软件显示约 6 分钟；1195 秒显示约 20 分钟且仍按原始秒数归类到所选 10 分钟以外。

此真实检查同时调用了两个模糊匹配请求（各约 0.95 秒），模型均返回无匹配，独立高德候选得到保留。合法关联与非法 ID 拒绝另由 HTTP 自动化验证，不把“无匹配”伪装成关联成功。

## 阶段 review 修复：并发关联与旧 ID

审查通过两个规划起点并发召回同一 POI 复现：一站已关联本地记录，另一站仍展示旧高德 ID 和缺失设施，旧 ID 详情返回 404。原因是关联等待后返回了旧对象，以及批次缓存没有重新读取该 POI 的正式记录。

修复后，`Catalog.get` 将已公开的 `amap_<poiId>` 沿 POI 关联解析到正式本地记录，缓存加载后同样成立；异步匹配完成时先重新读取关联，避免另一个站点已完成关联后返回旧对象。查询在分析前、分析完成后及已完成批次再次读取时刷新名称、设施与来源，按正式 ID 去重和重新分组。已有路线只在目标坐标相同的情况下保留，各站独立路线不互相覆盖；若目标实际变化则清除旧数值，等待显式重试。

新增三条 HTTP 回归覆盖并发两起点的独立路线、已完成站点随后被其他站关联、已保存旧 ID 在关联缓存加载后恢复。审查原脚本复验两站均为本地 ID、`matched`，旧 ID 详情 HTTP 200。包含最新阶段 02 修复的全套 48 条 HTTP/DOM 测试、类型检查及构建通过。未调用浏览器预览，也未额外调用真实供应商。

给规划客户端的兼容约定：`Candidate.sources` 保留高德 `poiId`；当已有选择为 `amap_<poiId>` 时，可将其对应到新批次的 `candidate.toiletId`。同一厕所出现在不同站点是合法的，去重仅作用于各站查询结果。旧 ID 的详情响应也会返回正式 `data.id`，可用于恢复本机保存选择。

## 通用修复反馈改进

在集成版本 `edcd310` 的有界诊断中，一次候选响应含八个不属于输入设施对象的依据字段；唯一修复在共同 20 秒截止时中止。校验与回退行为正确，但修复提示缺少具体字段问题和前次输出。诊断保存在执行机器的 `/private/tmp/readytogo-demo-notes/shichahai-ai-diagnostic.md`，未修改生产代码后才进入本次通用改进。

分析输出现在使用实际 `Facilities` 键构造有限枚举，并在提示中明确列出这些标识符；翻译标签、猜测别名均不当作字段接受。原有逐候选非缺失、零值、正面线索及明确肯否定保护保留。解析和匹配的原文、顺序、候选 ID 校验也使用受控问题分类。

唯一一次 JSON 修复包含最多 12,000 字符的拒绝响应（标注是否截断）与最多 16 条校验问题。每条问题只含有界字段路径、服务端定义的类别、可选允许值及长度限制；路径最多 8 段，允许值最多 32 项、每个字符串最多 160 字符。拒绝响应以 JSON 引用对象放在 assistant 消息，校验问题以 JSON 数据传入后续 user 消息；系统指令明确它们是待检查的 untrusted 数据，不能执行其中的命令。未知异常文本、供应商错误消息及堆栈不会插入提示，也不写入业务日志。

解析/匹配 12 秒、候选分析 20 秒、`maxRetries=0`、最多一次修复及共同截止均未改变。没有增加具体地点、特定输入或测试名称的生产分支，也没有猜测依据字段的别名。

新增五条 HTTP 测试覆盖具体反馈修复非法字段、缺失依据与原始否定的区别、修复再次非法时回退、上下文截断与日志边界，以及初次输出和修复仍共用同一期限。相关 24 条测试和全套 78 条 HTTP/DOM 测试、类型检查、构建均通过。

完成代码后仅做一次真实公共地点候选验证：匹配调用 1,176 ms；10 项候选首轮分析 11,491 ms；整体 HTTP 查询 20,543 ms。返回 `status=complete`、`analysisStatus=complete`、`pendingWork=false`，没有站点错误和路线未知候选。10 项 ID/依据字段/原始事实检查均通过，无非法字段、缺失依据、非法枚举或路线数字问题。本次未触发修复，修复路径由上述 HTTP 边界测试验证。记录为 `/private/tmp/readytogo-demo-notes/repair-feedback-live-results.json`，没有再次调用追求固定文案。

## 发布阶段修复：确定性保留原文上下文

发布前的真实解析保留了地点和否定坐便需求，却遗漏相对时间，说明仅要求模型提取时间备注仍不足以保证原文覆盖。修复把原文保留交给软件，模型继续负责地点顺序、检索词及显式需求。原提示中的时间归属规则被移除，模型备注不再作为显示依据；没有新增时间词表、具体地点或评测输入分支，也没有增加模型轮次。

解析先验证每个地点的 `originalText` 是输入中按顺序出现且不重叠的片段。软件仅为判断纯地点列表而移除这些片段：剩余内容如果全是明确允许的空白、列表标点和箭头，则备注为 `null`；问号、文字及有意义符号仍视为上下文。只要存在上下文，每个已解析站点均保留完整连续输入，并由软件标注 `noteKind: source_context`。不按标点擅自拆分，也不拼接片段或断言某个时间专属于某站。原文中的全局日期前缀或跨站后缀因此可以完整回看。

模型不能输出 `noteKind`，该额外字段会触发现有严格校验及最多一次修复。模型虚构或漏填的 `note` 不影响最终保留结果。输入与模型备注的长度边界均为 2000 字符，没有500字符截断；地点数量、重复顺序、需求提案、12秒解析/匹配、20秒分析和一次修复预算保持不变。只表达需求且没有解析地点的输入不会因此新增站点。

先以公开HTTP复现相对描述遗漏并确认红灯，再加入实现。新增16条HTTP回归覆盖中英不同时间、共享前后文、独立日期行、重复地点、地点内标点、缩写、emoji、问号、纯列表、完整2000字符、虚构备注被忽略、软件类型不可注入与需求边界；AI HTTP测试37/37通过，类型检查通过。独立设计复核与根代理代码复核均未发现阻断项，记录在 `/private/tmp/readytogo-demo-notes/source-context-design-review.md`。当前修复未发起新的真实模型调用，发布侧单次验证由工单07统一执行。

客户端配套将 `source_context` 作为可选字段保留至确认和 `PlanLocal.schemaVersion: 1`，并以折叠原文展示；编辑后转成普通备注。具体行为、长度与隐私口径见 [AI行程输入](../../docs/implementation/ai-itinerary.md)。
