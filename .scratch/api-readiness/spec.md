## 首版结论

首版是东城、西城的手机网页。外部运行时依赖为阿里百炼和高德 Web 服务；北京公厕使用仓库内 CSV 离线处理。上海接口作为扩城材料后补。

用户提供账户、凭据、必要的配置和数据元信息；开发负责请求封装、数据清洗、规则排序、输出校验、降级和前后端接口。PRD 中的 `/api/*` 是本项目要实现的接口，无需用户另外采购或开发。

### 百炼的具体用途

同一个模型服务接入可先覆盖三类调用，无需分别准备三个供应商：

1. 在线情况解析：任意语言描述映射为 PRD 枚举范围内的偏好 JSON；首次引导与结果页微调共用接入。
2. 在线推荐解释：仅解释服务端提供的候选事实，异步生成，失败使用规则模板。
3. 离线名称和地标文案：生成英、日、韩文本，缓存为 JSON，并按 PRD 抽检。

`qwen3.8-flash` 已通过短 JSON 连通性测试，暂作为项目默认。多语偏好解析、解释事实一致性和短超时下的稳定性仍需按 PRD 实测。结构化输出支持不替代服务端校验。

百炼官方区分按量模型服务与 Coding Plan / Token Plan。后两者仅供指定 AI 工具交互式使用，不能作为本产品后端凭据。API Key、地域和 Base URL 必须配套；不预先硬编码某个域名。依据：[百炼 Base URL 总览](https://help.aliyun.com/zh/model-studio/base-url)。

用户提供的开发 skill 可指导接入；只有用户明确选择复用已发布的百炼应用时，才将 APP_ID 纳入运行时配置，不默认要求创建 Agent、知识库或工作流。

### 高德需要的能力

| 能力 | PRD 中的用途 | 开发侧检查 |
| --- | --- | --- |
| POI 周边搜索 | 补充公厕及室内厕所候选 | 按返回类型精确筛选；读取 `business`、`indoor`；记录分页和覆盖状态 |
| POI 关键字搜索 | 用户手选起点、英文快捷地点映射后查询 | 必须返回用户可以点选的真实 POI |
| 步行路径规划 | 给候选提供真实步行耗时和距离 | v5 步行请求显式请求 `show_fields=cost`；读取 `cost.duration`，失败回退地图距离 |
| 坐标转换 | 浏览器坐标和政府原始坐标统一到高德坐标 | 政府数据原始坐标系先核实，保留原始值，不重复转换 |
| 高德网页路线 URI | 点击 Navigate 打开步行路线 | 按 PRD 使用网页模式，真机测试能否打开并正确显示起终点 |

四类 API 已用同一把 Key 完成基础调用。当前验证不代表完整地区覆盖、账户剩余额度或部署环境可用性。

P0 按 PRD 使用浏览器定位、结果卡和网页导航；若后续选择内嵌高德交互地图或使用高德 JS 定位插件，再准备 JS API Key 及安全配置。高德供应商细节和官方来源见同目录 `provider-references.md`。

## 仓库内北京 CSV 的实际状态

已读取：[data/BJ-ToiletInfo.csv](../../data/BJ-ToiletInfo.csv)。初步检查结果：

- 可按 `gb18030` 解码；每行 27 列。
- 有 13,156 条序号为数字的记录；另有标题、多行表头、空白行和末尾填报信息。
- 按“所在区县”精确计数，东城区 1,238 条、西城区 975 条，共 2,213 条。以上均为清洗、过滤及去重前数量。
- 数据包含厕所编号、名称、地址、经纬度、类别、指标状况、冲洗方式、第三卫生间、无障碍和设施等 PRD 所需字段。
- 文件标题为“2022年环卫设施（厕所）台账”；这不是文件在数据平台上的更新时间，不能用作 `govDataUpdatedAt`，也不能把本地获取时间写作数据更新时间。
- 首条记录包含 PRD 提到的经度 `16.7088`，说明坐标清洗仍需实际执行；本次未修改原文件，也未判定坐标系。

已有 CSV 足以开始清洗工作，无需重复提供文件。若以后希望由脚本从北京平台重新下载，再补 `BJDATA_KEY`；直接使用用户交付的文件不依赖该 Key。

原始来源暂依据 PRD 第 6.1 节；本轮读取该政府数据页面超时，未在线核实其当前文件更新时间。没有确切日期时保留未知，不能编造更新日期。

## 上海接口：扩城时的交付清单

北京首版不等待上海接口。若后续支持上海，应提供：

- API 文档/服务地址和鉴权方式；需要时提供 Key 或 Token。
- 一份脱敏成功响应及字段说明，尤其是稳定 ID、名称、地址、坐标、坐标系、设施和更新时间。
- 覆盖区域、分页/全量获取方式、限流和更新频率。
- 坐便、第三卫生间、无障碍等字段的实际含义；没有的字段保持未知，不能直接沿用北京证据等级。

本轮未获取上海接口文档，不预先断言其覆盖或字段能力。

## 无需额外准备的服务

依据当前 PRD，首版无需登录/短信、支付、评论、云数据库、对象存储、独立翻译 API、语音服务、图像识别或携程接口。偏好存在浏览器本地，公厕数据由服务端内存中的 JSON 提供，询问卡和界面文案为静态模板。

浏览器定位无需另购 API Key，但需要用户授权和安全上下文；手机远程访问准备 HTTPS，并实测失败后手选起点的流程。依据：[MDN Geolocation API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API)。

1. 先清洗现有 CSV，核对列对齐、过滤值、重复记录和坐标，产出可复现日志。

4. 完成一键急需、偏好保存、询问卡等自有接口和页面，并在 HTTPS 真机环境验证定位与导航。
