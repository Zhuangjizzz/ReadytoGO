## 已确认的范围

| 决策 | 结论 |
| --- | --- |
| Q1 用户任务 | 单起点急需：表达需求、查找候选、查看详情、导航与现场询问 |
| Q2 AI 职责 | 解析内容、调用高德搜索、匹配现有厕所资料、取得详情、输出结构化结果供网页渲染 |
| Q3 语言政策 | 语言影响界面与贴士，不推断坐便、设施或行动需求；切换语言保留显式偏好 |
| Q4 交付物 | 完整可运行网页及必要服务；讲解视频由用户自行录制 |
| Q5 本地匹配 | 高德返回周边厕所名称与位置；用名称检索本地厕所名称，召回语义相似度高的几条，AI 阅读后判断是否有大概率对应同一厕所的记录 |
| Q6 首次交互 | 首页输入一句情况直接查询，同时保留无需打字的一键急需；没有需求时按附近查找 |
| Q7 推荐决定权 | AI 在满足硬性要求的候选中选择、排序并解释，服务端校验事实和硬性条件 |
| Q8 失败体验 | 保留已有可靠结果；AI 不可用时直接查询本地资料，展示基础列表和能力受限提示，保留可用操作 |

用户明确要求结束本次范围讨论并收拢 PRD。本地匹配不增加关联不确定性的独立用户流程；算法、条数、阈值与内部边界在实施中决定。

## 对原有规则的收拢

| 原讨论点 | 收拢结果 |
| --- | --- |
| “近一点”与多个 5 分钟容忍 | 由 AI 权衡软偏好，保留硬性要求；不再固定采用逐层 5 分钟排序 |
| 轮椅与第三卫生间 | 轮椅首选需要明示无障碍证据，第三卫生间字段不能独自替代 |
| 微调只在前端重排 | AI 可按需求重新查询工具；网页显示变更并提供撤销，快照与缓存是实现选择 |
| 政府与高德的时段、覆盖 | 保留各自来源；政府无时段不覆盖高德时段，覆盖/错误按来源分别记录 |
| 语言默认需求 | 删除地区默认偏好；需求来自用户内容、标签和确认保存的偏好 |
| 独立首次引导 | 首页直接输入并查询；解析出的需求可修正，保存偏好由用户确认 |
| 管理间映射 Staffed | 展示“列有管理间”，不推断当前有人值守 |
| 模型返回 schema、澄清、无效字段 | 明确输出所需语义和校验边界，具体 schema 与处理策略由实施统一定义 |
| 关联歧义界面 | 不增加独立产品流程；按用户确定的名称召回与 AI 判断路径实现 |
| 阶段排期与演示目标 | 当前 PRD 只记录开发内容与完成条件，原稿保留作追溯资料 |

这些条目将已有要求与用户确认的原则落实到文档，不表示网页功能已完成或数据事实已验证。

## 实现选择与验证

名称语义检索的模型/算法、索引、召回条数、判断阈值、无匹配/多匹配内部处理，以及工具调用限制、重试、缓存和输出 schema 在实施中确定。开发者记录选择和样例验证，不把它们重新解释成未确定的产品范围。

数据清洗、坐标系、规范依据、贴士内容及工具能力仍需按[验收细则](../../docs/prd/acceptance.md)核验。完成标准包含实际工具调用与网页渲染，不能只用模型返回短 JSON 证明。
