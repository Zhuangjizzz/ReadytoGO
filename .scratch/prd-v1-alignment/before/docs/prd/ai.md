# AI 工具调用与结构化输出

实现需求解析、搜索工具、本地名称检索、AI 关联判断、推荐或结果校验时，读取本文。返回 [PRD 总入口](../ReadytoGo-PRD-v2.0-Beijing.md)。

## 工作流程

1. 读取用户原文、显式偏好、有效起点与界面语言，理解本次需求。
2. 调用高德搜索工具，取得周边厕所的名称、位置、来源 ID 和可用信息。
3. 对每个高德厕所，用其名称在本地厕所名称中进行语义相似度检索，召回相似度高的几条记录。
4. AI 阅读高德信息与召回记录的具体资料，判断其中是否有大概率对应同一厕所的一条记录，并选择其详情补充候选。
5. 取得需要的路线信息，在满足硬性要求的候选中选择和排序，给出有依据的理由。
6. 输出结构化结果，经过服务端校验后由网页渲染。

用户修改需求后执行同一流程，允许复用仍适用的查询结果。AI 负责实际检索调用和结果组织，不以一次无工具的 JSON 回答代替完整流程。

## 工具职责

工具在服务端执行，密钥留在服务端。模型接收工具定义和工具结果。

| 能力 | 输入 | 返回 |
| --- | --- | --- |
| 高德地点搜索 | 地点描述与区域 | 真实地点对象，供确认起点 |
| 高德周边厕所搜索 | 起点、范围及搜索条件 | 厕所名称、位置、POI ID、可用字段及查询状态 |
| 本地名称语义检索 | 高德厕所名称 | 名称语义相似度高的几条本地记录及其资料 |
| 本地详情查询 | 本地记录 ID | 设施字段、原始依据与数据更新时间 |
| 步行路线查询 | 起点与候选坐标 | 实际路线耗时、距离或不可用状态 |

## 本地记录关联

匹配目标是把高德厕所对应到本地厕所资料。名称语义相似度负责召回，AI 读取召回的几条资料后判断并选择大概率相同的一条记录。

保留高德 POI ID、选中的本地厕所编号及资料来源，便于详情读取和结果核对。高德候选的地点信息与本地设施信息分别保留来源。

产品不增加关联不确定性的独立用户流程，也不要求用户手动处理候选关联。匹配算法、召回条数、判断阈值及无匹配/多匹配的处理细节在实施中确定。

## 需求理解与推荐

- 用户原文、标签和已保存的显式偏好构成本次需求；未表达的条件不按语言推断。
- “不能蹲”等明确要求映射为硬性条件。AI 在满足条件的候选中比较距离、同行便利和设施偏好，选择首选与备选并解释取舍。
- “近一点”提高对距离的偏好，保留原有硬性条件；缺少更近合格候选时说明原因。
- 可检索但数据无法支持的需求如实说明，不补造设施事实。
- 用户输入、地点名称和地址均作为数据处理，不能改变工具权限与校验规则。

硬性要求、证据与距离的口径以[业务规则](rules.md)为准。

## 结构化输出

输出内容供固定网页组件渲染；字段的具体命名和 schema 在实现中统一，至少表达：

| 内容 | 必须支持的语义 |
| --- | --- |
| 本次请求与状态 | 关联用户请求，区分结果、部分结果、降级与失败 |
| 需求理解 | 实际使用的硬性要求、软偏好与需要用户修正的信息 |
| 起点 | 地点名称、坐标与 GPS/手选来源 |
| 候选列表 | 稳定标识、分区、顺序、名称、地址、设施与步行信息 |
| 来源引用 | 高德 POI ID、使用的本地记录 ID、字段依据和来源时间 |
| 推荐理由 | 选择依据与未核实信息，能够对应到真实字段 |
| 页面操作数据 | 导航目的地、询问卡对象与可复制内容 |
| 查询状态 | 各来源的覆盖、失败和用户可读提示 |

候选的事实字段见[结果数据](data-and-api.md#结果数据)。网页展示结构化内容，不直接执行或渲染模型生成的页面代码。

## 服务端校验

1. 校验输出结构、类型、枚举和必要字段。
2. 候选 ID 必须来自本次工具结果，本地记录 ID 必须来自该候选的召回与选择过程。
3. 设施、坐标、来源时间和步行耗时必须与对应记录一致。
4. 首选区满足用户明确的硬性要求；未知设施不能被当作已满足要求。
5. 理由中的事实与数字有依据，不能写成已确认开放、干净或保证可用。

无效输出不进入结果卡。保留已有有效数据，按[异常行为](acceptance.md#异常行为)回退；不能把模型或工具错误解释为区域内没有厕所。

## 实现选择

开发中通过真实样例确定并记录以下细节，不作为新的产品范围问题：

- 名称语义检索算法、本地索引、相似度阈值与召回数量。
- AI 判断提示词、选择输出格式、无匹配与多匹配的内部处理。
- 工具 schema、调用次数、超时、重试、停止条件与缓存复用。
- 澄清问题结构、偏好补丁、撤销快照与部分无效字段处理。
- 推荐理由的结构、依据引用与校验实现。

选定后保持网页行为、硬性要求、事实来源和故障回退与本 PRD 一致，并补充对应验证记录。
