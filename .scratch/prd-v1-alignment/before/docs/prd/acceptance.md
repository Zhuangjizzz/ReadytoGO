# 验收与异常状态

验证正常流程、AI 工具执行、数据质量、失败回退或交付完整性时，读取本文。返回 [PRD 总入口](../ReadytoGo-PRD-v2.0-Beijing.md)。

## 主流程验收

| 场景 | 通过条件 |
| --- | --- |
| 首页直接输入 | 输入一句情况即可发起查询，网页展示实际使用的需求与结果；无需完成独立引导页 |
| 一键急需 | 不输入文字也能查询；没有偏好时按附近查找，有已保存显式偏好时使用它 |
| 起点 | 定位成功和手选来源分别显示；自由文字未经地点确认不能成为坐标 |
| 工具搜索 | 一次真实请求能追溯到实际高德搜索，取得周边厕所名称、位置和 ID |
| 名称匹配 | 高德厕所名称进入本地名称语义检索，返回几条相似记录供 AI 阅读和判断 |
| 详情补充 | AI 选择的本地记录来自召回结果；使用的设施字段与该记录一致 |
| 推荐 | AI 在满足硬性要求的候选中排序和解释，程序校验后展示 |
| 结构化渲染 | 结果通过约定 schema 与事实检查，网页正确渲染卡片、详情和操作 |
| 导航与询问 | 网页导航目标与当前候选一致；询问卡对应当前厕所及缺失信息 |

单独证明模型返回合法 JSON，不能替代上述工具执行与网页渲染验证。

## 需求与信息口径验收

1. “妈妈不能蹲”解析为必须有坐便线索并带有老人同行信息；首选不使用坐便未知候选。
2. 轮椅需求按明示无障碍证据筛选；不能仅用第三卫生间字段代替。
3. “近一点”保留已有硬性条件。存在更近的合格候选时应反映距离偏好；没有时解释原因，不强行改变首选。
4. 需求变更可见且能撤销，用户确认保存的偏好在本地存储可用时刷新后仍可用。
5. 语言切换不改变偏好；英日韩界面、AI 文案与中文原名/地址正常显示。
6. 证据标记符合[坐便证据](rules.md#坐便证据)，名称本身不升级证据。
7. 设施等级按来源字段计算；管理间不表述为当前有人值守，星级不表述为实时卫生。
8. 公示时间未知保持未知；明确时段冲突从首选移出，不出现 `Open now`。
9. 步行时间只来自真实路线；地图距离不换算为伪造分钟数，较远候选仍可展示。
10. 必须坐便且默认范围无首选时扩大查询，保留已有备选与已扩大提示。
11. 坐便、开放与进入条件的询问卡不调用模型生成问题，也不自动升级证据。
12. 来源行能区分政府文件更新日期与高德取数时间。

## 异常行为

| 环节 | 要求 |
| --- | --- |
| AI 失败或超时 | 保留已获得并通过校验的结果；直接查询本地资料展示基础列表，明确推荐能力受限 |
| 高德搜索失败 | 保留已有结果，使用本地基础查询；说明地图搜索当前不可用 |
| 本地资料读取失败 | 保留可用的高德结果，缺少的设施信息保持未知，不编造补充字段 |
| 个别步行路线失败 | 保留候选，展示地图距离或步行时间不可用，其他结果照常 |
| 输出结构或事实校验失败 | 无效内容不渲染，保留有效数据或使用基础列表，不能把失败表述为没有厕所 |
| 地点搜索无结果/失败 | 分别显示空结果或可重试错误；不把用户文字当已确认地点 |
| 定位拒绝/超时/不支持 | 显示对应原因并提供手选起点，手选不得伪装成 GPS |
| 数据文件缺失 | 服务启动时报告数据加载错误，不宣称本地回退可用 |

回退列表继续遵守硬性要求及分区口径：不满足要求的只能作为明确标记的备选。详情、询问卡与可用导航入口保留。

显示已有结果时不等待所有模型或工具完成。调用重试与总耗时有实现边界；记录实际耗时，不以未测结果承诺“秒开”。

## 数据与工具验证

- 政府数据：3 行列对齐样例、取值统计、区域数量、剔除及修复日志齐全。
- 坐标：覆盖十进制度、度分秒、经纬互换和缺位记录；20 个已知公厕叠图核对，错误坐标不进入结果。
- 离线增强：30 条翻译与地标描述抽检，记录问题与修正，证据和设施等级可追溯。
- 高德：精确过滤厕所类型，母婴室不作为厕所；分页覆盖完整与受限分别表达；缺失楼层保持未知。
- 名称匹配：保存代表性高德名称、召回记录、AI 选择及使用的详情，核对完整调用顺序和资料来源。
- 路线：有坐便线索的候选不因缺少路线或不在直线最近的少数点内而消失。
- 输出：不存在的 ID、未召回的本地记录、无依据的设施或数字无法通过校验。

算法、召回条数与判断阈值的具体验证按[实现选择](ai.md#实现选择)记录，不增加独立的关联不确定性用户流程。

## 网页交付完成条件

- 首页输入、一键急需、需求微调、详情、导航、询问卡和贴士可完整使用。
- 必要的服务端、数据加载与配置流程可运行；README 记录实际启动方法。
- 密钥留在服务端，示例配置不含凭据，定位坐标不写入持久日志。
- 正常流程、硬性要求及故障回退的验证结果齐全。
- 手机尺寸、支持语言和目标浏览器的导航操作经过检查。

交付物是完整网页及运行所需资料。用户自行录制讲解视频，录制工作不计入网页完成条件。

## 验证记录

真实情境记录起点、候选 ID、使用的本地厕所编号、来源字段、路线耗时与取数时间，并对照网页展示的证据、理由和排序。

记录首次结果、AI 推荐结果的实际耗时，以及通过、失败或环境限制。若使用历史响应测试，显著标记 `Historical Amap sample · captured [time]`，不能冒充实时结果。
