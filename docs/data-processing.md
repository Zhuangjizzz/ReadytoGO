# 数据导入与最小查询记录

本记录对应工单 [01](../.scratch/demo-development/issues/01-data-nearby.md)，验证日期为 2026-10-09（Asia/Shanghai）。

## 正式导入

运行 `npm run import:data`，读取 `data/BJ-ToiletInfo.csv` 的 GB18030 内容，输出 `data/generated/catalog.json`。输入不被修改。也可传入 `-- --input <CSV路径> --output <JSON路径>` 用于复现。生成数据与位置缓存不提交 Git；服务启动时缺少正式导入产物会自动导入原文件。

实际导入 13,156 条带数字序号记录，生成 13,124 个实体，合并 32 条重复记录，未跳过有名称的记录。7,887 个原始坐标可解析，5,237 个实体的坐标缺失或无法可靠解析。原表坐标系未知，因此导入时可直接用于 GCJ02 查询的位置数为 0；查询过程中自动匹配得到高德位置后即可算路。

- 精确列映射区分第三卫生间、宽泛无障碍设施、无障碍厕所间、全部无障碍、无障碍厕位、管理间、盥洗室。
- 数值零保留，空白和缺失符为 `null`；源文件名、原行号、政府编号及原始字段保留。
- 解析十进制和合法度分秒，明确经纬互换可修复；不为 `16.7088` 等异常数字猜补前缀。原 CSV 的未转义度分秒秒符采用宽松引号解析，完整输入计数由自动化检查。
- 实体身份使用名称、区县、地址及可靠原始位置的确定性摘要；无位置的记录使用原始内容参与身份。政府编号不是唯一键。重复导入获得相同 ID，明确重复记录合并来源行。
- 本地原始位置仅帮助召回和匹配，不直接贴上 GCJ02。原始设施不随位置缓存刷新或被旧缓存覆盖。

## 地点、匹配与路线

高德适配器使用 POI v5 搜索、周边搜索和步行 v5，步行显式请求 `show_fields=cost`，只接受 `route.paths[].cost.duration` 秒与 `distance` 米。缺字段或非法响应为 `provider_error`；明确成功且空路径列表为 `unreachable`。路线未知不合成步行分钟。

自动匹配要求同一区县，并比较完整门牌号（含甲乙前缀）和完整末级道路名；门牌数字不能按文本前缀匹配，例如 1 号与 10 号保持独立。相同道路/门牌允许附加入口文字；已给出的道路或门牌冲突不能被同名覆盖。原始位置存在时，必须与高德位置在 800 米匹配容差内，否则保留独立候选；缺原始位置时可用唯一精确地址。歧义并列同样保留独立高德候选。没有为具体景点、测试语句建立映射。

实际高德 `200304` 返回“婴儿换洗间/哺乳室/母婴室”，不等于成人厕所。查询过滤仅保留 `200300`–`200303`，旧独立 POI 缓存同样过滤。保留供应商实际分类字段，设施分析可继续使用来源。

位置缓存只持久化关联、位置与供应商字段；恢复缓存时以当前 CSV 的设施、来源和停用状态为准。已知 POI ID 去重，按统一 GCJ02 起终点缓存真实步行结果。源文件未知坐标不被当作浏览器 GPS 转换。

导入和查询共用来源状态解释：备注中的“未开放”“尚未对外开放”等当前状态派生为 `out_of_service`，即使指标状况仍为“现有”，也不进入附近或规划推荐。明确重新开放可更新状态，历史和否定语句不会当作当前关闭；原始字段与备注保持原样。

## 真实联调结果

有限真实联调已跑通以下路径：

- “什刹海”地点搜索返回北京候选；本地“后海南沿1号旁”自动匹配后返回 **249 秒 / 311 米**，第三卫生间原值为 **0**。
- 同批本地“羊房胡同23号旁”返回 **504 秒 / 630 米**，第三卫生间原值为 **1**；“小新开胡同3号旁”返回 **512 秒 / 640 米**，原值同为 **1**。三者都同时保留北京台账与高德来源。
- 英文 `Beijing Zoo` 通过正常地点接口返回“北京动物园”，无需固定景点翻译表。桌面 Chrome 的 390×844 窄屏操作完成地点选择和真实附近查询，9 张初始卡片可见、无脚本错误、无横向溢出。此项是窄屏模拟，不声称已完成实际手机验收。

最初并发突发调用出现高德 `10021 / CUQPS_HAS_EXCEEDED_THE_LIMIT`。保留最多 5 个在途请求，统一请求起始间隔经 250ms、350ms 联调后调整为保守的 **500ms**。500ms 是运行初值，不代表配额保证。错误日志只记录安全的供应商错误码和固定形式信息；没有原始请求 URL、密钥或位置。请求日志统一关联 `requestId`、路由模板、耗时与错误码。

结果支持第一批 10 个算路、后续游标、`pendingWork` 与终态 `partial`。失败候选保留 `null` 路线值，终态部分失败不自动循环重试，用户可显式重试。完整五组规则、60 个处理上限后的延续、多站队列等待与总体时限由后续工单扩展。

## 自动化与阶段审查

`npm test` 通过正式导入 CLI 与公共 HTTP 覆盖：GB18030、多行表头、设施零/缺失与相邻列、稳定身份和重复来源、完整原 CSV、资料自动匹配、真实路线单位、异常路线不伪造耗时、北京外/非法输入、旧缓存不覆盖新资料、同一请求日志 ID 与敏感内容排除。

初次导入/HTTP 测试先因缺失实现或缺失路由失败；完整原文件暴露引号问题后修复；独立阶段审查发现旧缓存覆盖问题，由失败回归证明修复。`npm run check` 与 `npm run build` 为每次交付检查。

500ms 起始间隔的最终有界真实复验：10 条路线均返回 `success`；不据此承诺供应商始终成功。

## 阶段审查补充：门牌与位置冲突

独立 merger 复现旧规则把数字前缀不同的门牌误关联。本轮先加入正式 GB18030 导入→公开 HTTP 的回归：不同门牌数字、数字前缀、甲乙号、不同道路、道路后缀、已知位置冲突都保留独立 POI；同门牌附加入口说明继续匹配。初次 7 条场景中 6 条失败，修改通用匹配后全部通过；另补无门牌时的明确道路冲突，合计 15 个测试通过。

匹配缓存增加规则版本 2。旧宽松规则生成的关联不恢复，由新规则重新关联；当前来源设施仍不被位置缓存覆盖。
