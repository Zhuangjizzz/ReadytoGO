# 附近推荐与批次行为

工单 [02](../.scratch/demo-development/issues/02-nearby-rules.md)，验证日期 2026-10-09（Asia/Shanghai）。

## 规则与来源

`src/server/rules.ts` 统一解释设施备注、原始字段、开放时间和进入要求。明确成人坐便肯定为 `documented`；第三卫生间、无障碍厕所间或厕位可推断 `inferred`。明确否定和儿童专用不能进入成人坐便推荐；无法解释的肯否定冲突为 `unknown` 并设置 `seatConflict=true`。儿童器具数量与“无坐便信息”不等于成人坐便事实。原始字段与备注保持原样。

门票、消费、禁止游客等只有资料明确表达时才派生进入条件。附近排除不可用及可解析营业时间预计关闭的记录；规划保留周期性关闭候选。营业时间使用上海时区，支持简单每日时间段、常见星期范围和跨午夜区间；节假日或季节等复杂说明保留原文并标为未知。

五个组互斥；需要坐便时的普通厕所（包括路线未知或带进入条件的普通厕所）由 `ordinaryAlternative` 标识，前端统一由用户展开。范围判断用原始秒数；更远坐便候选保留真实路线。成功路线按秒数、米数、稳定 ID 排序，路线未知按直线距离排序。真实步行不可达不进入步行推荐。

## 批次和缓存

- `batchCursor` 标识当前批次，重复读取及短轮询复用同一计算；`nextCursor` 只用于用户明确加载下一批。游标在服务端保存，绑定有效查询条件。
- 一次自动等待只处理当前 10 个候选，不自动跨 `nextCursor`，因此不会自动越过每次 60 个的预算。用户点击加载更多可以继续剩余候选，候选目录不再在第 60 个被截断。每个供应商范围最多读 8 页，重复或空页停止继续获取。
- `pendingWork=true` 才自动补拉；终态 `partial` 不再自动发请求。`retry=true` 可重试本批失败路线，或在无游标时开启新一轮有限查询。已成功路线沿用缓存。
- 查询计算键独立于 `queryVersion`、标签和显示顺序。响应始终带本次请求版本；页面同时检查版本及条件，不能只依赖网络取消。
- 原有 500ms 请求起始节流和 5 个在途上限保留。多站共享供应商实例，队列等待预算 90 秒，实际 HTTP 超时 5 秒；批次总上限 120 秒，页面最多自动等待 130 秒。等待上限不冒充供应商调用时限，超限后保留已有结果，未完成路线数字为 `null`。
- 已有可用本地候选先开始算路；外部召回继续补充，首个 HTTP 响应等待初值 150ms。

`QueryService.setCandidateAnalyzer` 是候选分析接入点。每批算路后调用一次并继续受批次截止时间保护；分析只接收经校验的名称、说明和允许的坐便推断，保留原路线、坐标、来源和进入字段。明确肯定、否定、资料冲突不能被模型推断覆盖，模型不控制分组排序。05 负责模型的独立 12 秒预算和实际分析接线。

## 页面与验证

`NearbyPage` 持有附近筛选、分批结果、请求版本和展示状态；`ToiletCard` 共用路线格式及设施信息。`App` 已接入可运行的附近页面。03 在合入本票后负责主页、地图、定位、详情、导航、询问卡最终接线；组件边界已协同确认。

验证命令：`npm test`、`npm run test:dom`、`npm run check`、`npm run build`。当前 25 个 HTTP/导入测试和 2 个离线 DOM 测试通过，覆盖 600/601 与 1200/1201 秒、跨午夜、设施冲突、73 个候选完整分页、重复批次、终态部分失败、显式重试及总等待上限。DOM 测试使用隔离 JSDOM 与固定 API 边界，无页面服务或浏览器访问。

本票没有新增实际应用浏览器预览或截图：根任务的 Browser Use 明确拒绝之后，只进行 HTTP、构建和离线组件验证，没有换浏览器或端口绕过。此前阶段 1 的窄屏证据仍保留；最终视觉与真机验收由交付记录如实说明。
