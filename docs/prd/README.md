# ReadytoGo Demo 产品需求

状态：可进入开发。确认日期：2026-10-09。

面向北京入境游客，完成找附近厕所、按景点规划、查看推荐理由和打开导航的手机网页 Demo。交付重点是展示数据收集与整理、AI 分析、软件开发能力和产品想法的可行性。

本文与下列五份细则共同构成当前需求。以用户确认的 Demo 范围开发，不把数据更新、现场核验、人工审批或生产级审计作为前置条件。范围调整见[决策记录](../../.scratch/prd-v1-alignment/spec.md)。

## 要交付的能力

| 能力 | Demo 内容 |
| --- | --- |
| 手机网页 | 默认英文，可切换中文；地点保留中文原名与地址，无需登录 |
| 找附近厕所 | 定位或手选北京起点，选择无特殊要求或需要坐便，比较列表与地图 |
| 景点规划 | 按用户顺序添加 1–10 个景点，逐站给出推荐和备选，支持替换与跳过 |
| AI 分析 | 解析中英行程与需求、辅助地点检索和资料匹配、结合设施与路线生成推荐说明 |
| 数据整合 | 使用现有公厕数据，完成清洗、自动匹配、去重和查询，接入高德地点与路线 |
| 现场使用 | 厕所详情、高德 App/网页导航、复制中文地址、五句固定双语询问卡 |
| 本机保存 | 保存当前行程、语言、需求和用户选择，支持恢复与清除 |
| 展示与交付 | 完整可操作流程、运行说明和简洁的数据处理与 AI 分析记录 |

即时搜索以手动控件为主；自然语言即时搜索为后续扩展。首版包含行程 AI 辅助输入及推荐说明，模型不可用时仍可手动完成搜索和规划。

首版范围外：账号、云端同步、历史行程库、用户反馈后台、现场核验系统、实时语音、多语言扩展、轮椅路线和纸巾等额外筛选。规划保留用户景点顺序，不计算完整交通行程、到达时间或定时提醒。

## 开发顺序

1. 导入现有数据，跑通北京地点查询、资料匹配和附近候选。
2. 完成列表、详情、地图和导航，形成单起点流程。
3. 复用查询能力完成逐站规划、替换、跳过和本机保存。
4. 接入行程解析与候选分析，展示结构化结果和推荐说明。
5. 按[验收清单](acceptance.md)检查演示流程，整理运行说明与展示材料。

每步以可运行的功能为完成依据。模型、存储和匹配实现采用现有项目条件与简单可用的方案；不要为 Demo 增加通用平台。
