# Demo 验收

检查可操作流程、AI 展示、异常恢复和交付物时，读取本文。返回 [PRD 总入口](README.md)。

## 演示主线

1. 展示现有公厕文件经过字段整理、位置匹配和去重后进入应用，说明使用了哪些数据。
2. 从一个北京起点查附近厕所，切换坐便需求，查看卡片、地图、设施线索和 AI 推荐说明。
3. 粘贴一段中英行程，展示真实 AI 解析、确认景点和逐站推荐，操作替换、跳过与顺序调整。
4. 从详情打开高德导航或复制地址，展示双语询问卡；刷新页面恢复当前行程。

演示时保留少量输入、模型输出和页面结果，说明数据处理、AI 分析与软件交互如何配合。可以使用固定起点重复演示；供应商故障时可用明确标注的缓存或演示样例继续讲解。

## 功能检查

| 场景 | 通过条件 |
| --- | --- |
| 数据导入 | 现有文件能生成可查询数据，0 和缺失区分，重复导入不重复展示相同实体 |
| 位置匹配 | 自动匹配结果能用于地图；无匹配保留独立候选，个别缺位置不阻塞整个流程 |
| 默认搜索 | 定位或手选后能看到当前起点、附近结果及加载状态 |
| 步行范围 | 普通候选使用 10/20 分钟；展示分钟与实际路线一致，边界按原始秒数判断 |
| 坐便需求 | 有设施线索的推断候选可成为主推荐，卡片解释依据；未知信息不会变成已核验事实 |
| 更远候选 | 超时限的坐便候选在扩展范围内仍可查看，显示实际距离时间 |
| 进入与开放 | 可用来源字段正确显示；门票/消费开关生效；规划不因当前周期闭馆删除候选 |
| AI 行程解析 | 景点顺序与需求正确、否定不反转；同名和超站数有编辑入口，确认前保留旧行程 |
| AI 分析 | 正常演示真实调用模型，说明引用输入中的设施和路线；候选 ID 与页面对应 |
| 逐站操作 | 单站与多站可生成，替换、跳过、重排和单站重试可用 |
| 导航 | 起终点正确，切换当前位置后更新路线；网页与复制地址入口可用 |
| 双语与询问卡 | 中英切换、中文原名、五句询问卡及手机触控可用 |
| 保存与恢复 | 刷新恢复一份行程，清除后选择和缓存被清理，存储失败可继续操作 |
| 异步结果 | 旧查询或旧行程版本的响应不覆盖新选择 |

对容易出错的业务边界编写少量自动化测试，其余用可重复的页面操作检查。Demo 验收以这些功能为准，不继承原稿中的核验有效期、真实试点名额和全量审计要求。

## 异常恢复

| 异常 | 页面行为 |
| --- | --- |
| 定位拒绝或超时 | 转入手选起点，不反复请求权限 |
| AI 超时或输出无效 | 保留文本和候选，行程手动编辑，推荐使用规则说明 |
| 地图搜索不可用 | 展示已有本地结果和重试入口 |
| 本地资料缺失 | 高德独立候选继续展示，设施缺项标未知 |
| 部分路线失败 | 保留其他结果，失败项显示距离或路线暂不可用 |
| 某站失败 | 成功站可操作，失败站单独重试 |
| 地图或 App 加载失败 | 列表、网页路线和复制地址保持可用 |
| 当前范围无结果 | 提供扩大范围和更换起点，与服务错误区分 |

## 完成条件

- 附近搜索、景点规划、详情、导航、询问卡与保存形成可运行的手机网页流程。
- 数据导入、自动匹配和 AI 调用实际跑通，能用样例说明处理结果。
- 提供代码、依赖与启动说明、无凭据的配置示例、简短的数据处理记录和功能检查结果。
- 至少在一个实际手机浏览器完成主线演示，并检查窄屏、中英文字和导航降级；其他浏览器兼容问题按实际记录。
- 验收记录说明通过项和已知限制。讲解视频由用户自行录制。

软件功能检查不要求到现场采集新数据，也不以补齐全市资料作为交付条件。
